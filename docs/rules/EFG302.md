# EFG302 — Write-blocking PostgreSQL index creation

The PostgreSQL index is not configured for concurrent creation. When exactly one provider-generated SQL statement is tied to the normalized operation and has the expected `CREATE INDEX` shape for its table, it is retained in `providerSql` as evidence; workload-dependent lock and wait behavior remains uncertain.

This finding is asserted with `HIGH`/`high` confidence only when the repository's real PostgreSQL integration gate has verified the provider behavior behind the claim and the shipped provider engine evidence manifest covers EFG302 for the Npgsql provider. That gate runs the provider-generated statement against a real engine and records that non-concurrent index creation blocks concurrent writes while `CREATE INDEX CONCURRENTLY` succeeds outside a transaction and is rejected inside one. Missing, ambiguous, unrelated, or shape-mismatched SQL, and missing engine evidence, leave this finding explicitly `UNVERIFIED`. Use the Npgsql concurrent option when appropriate and honor its transaction requirements, then validate production lock behavior against your own workload.
