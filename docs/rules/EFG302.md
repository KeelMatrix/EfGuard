# EFG302 — Write-blocking PostgreSQL index creation

## When It Triggers

The PostgreSQL index operation is not configured for concurrent creation.

## Why It Matters

Non-concurrent index creation can block concurrent writes. When exactly one provider-generated SQL statement is tied to the normalized operation and has the expected `CREATE INDEX` shape for its table, EfGuard retains it in `providerSql` as local evidence.

## Remediation

Use the Npgsql concurrent option when appropriate and honor its transaction requirements. Validate production lock and wait behavior against your workload.

## Limitations

The finding is promoted to `HIGH`/`high` confidence only when the repository's real PostgreSQL integration gate verifies the behavior and the shipped provider engine evidence manifest covers EFG302. Missing, ambiguous, unrelated, or shape-mismatched SQL, or missing engine evidence, leaves it `UNVERIFIED`. The integration evidence records that non-concurrent index creation blocks concurrent writes while `CREATE INDEX CONCURRENTLY` succeeds outside a transaction and is rejected inside one. Runtime behavior remains workload-dependent.
