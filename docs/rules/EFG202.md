# EFG202 — Unsafe column alteration

## When It Triggers

The operation narrows a type, length, precision, scale, or nullability. Length narrowing includes unbounded-to-bounded text changes where the previous column had no maximum length and the target column does.

## Why It Matters

The conversion can reject existing values or writes from an older application generation, and it may lose data or reduce rollback options.

## Remediation

Add a compatible representation, transform data explicitly, switch application reads and writes, and enforce the narrower shape in a later contract step.

## Examples

EfGuard treats `nvarchar(max)`, `varchar(max)`, `ntext`, and PostgreSQL `text` as unbounded text. Representative mappings:

| Provider | Previous | Target |
| --- | --- | --- |
| SQL Server | `nvarchar(max)` | `nvarchar(32)` |
| PostgreSQL | `text` | `character varying(32)` |

## Limitations

Widening (`nvarchar(32)` back to `nvarchar(max)`) and changes without previous-column evidence are not reported by this rule. EfGuard does not inspect existing values, so verify that stored data fits the narrower shape before applying the migration.
