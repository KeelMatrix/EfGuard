# EFG202 — Unsafe column alteration

The operation narrows a type, length, precision, scale, or nullability. Transform data explicitly and transition application reads/writes before enforcing the narrower shape.

Length narrowing includes unbounded-to-bounded text changes, where the previous column had no maximum length and the target column does. EfGuard treats `nvarchar(max)`, `varchar(max)`, `ntext`, and PostgreSQL `text` as unbounded text and reports the change when the extracted previous column has no maximum length. Representative mappings:

| Provider | Previous | Target |
| --- | --- | --- |
| SQL Server | `nvarchar(max)` | `nvarchar(32)` |
| PostgreSQL | `text` | `character varying(32)` |

Widening (`nvarchar(32)` back to `nvarchar(max)`) and changes without previous-column evidence are not reported by this rule. The tool does not inspect existing values, so verify that stored data fits the narrower shape before applying the migration.
