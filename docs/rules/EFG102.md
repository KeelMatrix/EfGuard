# EFG102 — Required column may reject existing rows

## When It Triggers

A non-null column is added without a detectable default.

## Why It Matters

Existing rows may not satisfy the new requirement, so applying the migration can fail or create an unsafe rollout state.

## Remediation

Add the column as nullable or with a safe server default, backfill it in bounded batches, deploy code that requires it, and enforce non-nullability in a later contract step.

## Limitations

EfGuard cannot prove existing row counts or provider-specific default evaluation. Review the generated SQL and the data state before applying the migration.
