# EFG101 — Rolling-deployment incompatibility

## When it triggers

The previous application model still maps a table or column that the target migration drops or renames, or the current application model requires an element absent from the previous schema.

## Why it matters

Under a rolling deployment, the incompatible overlap state can break application instances that are still serving traffic. Under `expand-contract`, a previous-application + target-schema mismatch is advisory because the configured strategy treats it as a contract step that must occur after retirement. Under `blue-green`, overlap states are not required.

## Remediation

Use an expand/transition/contract rollout: add a compatible representation, deploy code that can work with both generations, move reads and writes, retire older instances, and remove the old schema in a later contract step.

## Limitations

Static analysis cannot inspect live queries, traffic, or deployment order. It evaluates only the application models and migration evidence supplied to the scan.
