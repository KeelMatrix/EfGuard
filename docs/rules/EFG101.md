# EFG101 — Rolling-deployment incompatibility

The previous application model still maps a table or column that the target migration drops or renames, or the current application model requires an element absent from the previous schema. Under rolling deployment this is a blocking overlap-state finding. Under `expand-contract`, a previous-application + target-schema mismatch is advisory because the configured strategy treats it as a contract step that must occur after retirement; under `blue-green`, overlap states are not required. Static analysis cannot inspect live queries, traffic, or deployment order.
