# EFG301 — Potentially blocking SQL Server index creation

## When it triggers

The SQL Server index operation is not marked for online creation.

## Why it matters

Offline index creation can block concurrent writes. When exactly one provider-generated SQL statement is tied to the normalized operation and has the expected `CREATE INDEX` shape for its table, EfGuard retains it in `providerSql` as local evidence.

## Remediation

Evaluate SQL Server/Azure SQL online-index support and configure online creation where supported. Otherwise schedule the operation for an appropriate maintenance window, then validate production lock duration against your workload.

## Limitations

The finding is promoted to `HIGH`/`high` confidence only when the repository's real SQL Server integration gate verifies the behavior and the shipped provider engine evidence manifest covers EFG301. Missing, ambiguous, unrelated, or shape-mismatched SQL, or missing engine evidence, leaves it `UNVERIFIED`. The integration evidence records that offline index creation blocks concurrent writes while `WITH (ONLINE = ON)` is accepted. Runtime lock duration still depends on engine edition, version, index shape, workload, and deployment conditions.
