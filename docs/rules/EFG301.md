# EFG301 — Potentially blocking SQL Server index creation

The SQL Server index is not marked online. When exactly one provider-generated SQL statement is tied to the normalized operation and has the expected `CREATE INDEX` shape for its table, it is retained in `providerSql` as evidence; runtime lock duration still depends on engine edition, version, index shape, workload, and deployment conditions.

This finding is asserted with `HIGH`/`high` confidence only when the repository's real SQL Server integration gate has verified the provider behavior behind the claim and the shipped provider engine evidence manifest covers EFG301 for the SQL Server provider. That gate runs the provider-generated statement and the online alternative against a real engine and records that offline index creation blocks concurrent writes while `WITH (ONLINE = ON)` is accepted. Missing, ambiguous, unrelated, or shape-mismatched SQL, and missing engine evidence, leave this finding explicitly `UNVERIFIED`. Configure online creation where supported or schedule a maintenance window, and validate production lock duration against your own workload.
