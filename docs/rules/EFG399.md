# EFG399 — Unverified operation or compatibility history

Raw SQL and custom operations are outside the high-confidence semantic rules. Review SQL and rollout order manually. Unknown operations are never treated as safe.

For the default `rolling` strategy, EfGuard also reports this diagnostic whenever no baseline is supplied: the scan has no evidence for the previous application/schema generation, so compatibility cannot be inferred. A supplied compatible baseline is sufficient for the default `minimumCompatibleVersions: 1` policy. If `minimumCompatibleVersions` is greater than one, one baseline reference is still insufficient. Supply the available baseline history or explicitly override/disable EFG399 only when the deployment policy accepts that uncertainty. Missing history is never inferred as compatible.
