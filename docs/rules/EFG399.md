# EFG399 — Unverified operation or compatibility history

## When It Triggers

The migration contains raw SQL or a custom operation outside EfGuard's high-confidence semantic rules. Under the default `rolling` strategy, EfGuard also reports this diagnostic when no baseline is supplied or when `minimumCompatibleVersions` is greater than one but only one baseline model is available.

## Why It Matters

Unknown operations and missing compatibility history do not provide enough evidence for a clean verdict. Unknown operations are never treated as safe.

## Remediation

Review the generated SQL and rollout order manually. Supply baseline history that represents the required compatibility generations, or explicitly override or disable EFG399 only when the deployment policy accepts that uncertainty.

## Limitations

A supplied compatible baseline satisfies the default `minimumCompatibleVersions: 1` history requirement, but operation-level findings still apply. EfGuard does not reconstruct application generations that are absent from the selected evidence. Missing history is never inferred as compatible.
