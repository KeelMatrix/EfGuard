# EFG303 — Foreign-key validation and locking risk

Existing orphan rows or validation locks can fail or delay a new foreign key. Validate and repair data before adding the constraint.

The locking part of this claim is asserted with `HIGH`/`high` confidence only when the repository's real SQL Server and PostgreSQL integration gates have verified the provider behavior and the shipped provider engine evidence manifest covers EFG303 for the provider. Those gates record that adding a foreign key holds a table lock that blocks concurrent writes until the transaction completes. Without engine evidence the finding is reported as `UNVERIFIED`. Validate data before adding the constraint, use provider-supported online or not-valid patterns where available, and measure lock duration against your own workload.
